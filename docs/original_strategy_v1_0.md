# BTC 多周期结构 × 强支撑压力 × 波段过滤 × 流动性订单流交易体系 V1.0

**版本日期：2026-11-20｜定位：可执行的人工交易 SOP 与待验证的量化研究方案；不是已经盈利的交易系统。**

## 0. 一句话原则

**先看环境（方向），再找位置（强支撑/压力），用波段过滤器观察动能阶段，再等价格形成可验证的结构信号，最后结合订单流检查反证；符合预设风险与收益条件才进场。**

整合范围：

1. TiaBTC 公开分析思路所归纳的“五步漏斗”（讨论框架，不代表其私人交易规则）。
2. 用户上传的《多周期强支撑强压力 v3.3》（Pine v6，`indicator()`）。
3. 用户上传的《Eric Swing Filter v1.9.10》（Pine v6，`indicator()`，文件明确标记“当前实验版未通过 TradingView 编译/回放验证”）。
4. 先前建立的《5-Step Liquidity Sweep》V1.0 和 V1.1（Pine v6，`strategy()`；已见亏损回测，未验证正期望）。

| 模块 | 主要功能 | 不能代替什么 |
|---|---|---|

**关键工程边界**：在 TradingView 上加载两个 `indicator()` 和一个 `strategy()` 并不意味着第三个脚本自动获取前两个脚本的内部变量或区域池。要形成统一自动化策略，需重新实现信号接口或将核心引擎明确整合到同一个 Pine `strategy()`，并做非重绘、时间对齐与回测验证；警报共存不等于策略联动。

## 2. 六层交易决策架构

1. **环境**：日线/4H趋势、波动条件、是否震荡或重大事件窗口。输出 `偏多 / 偏空 / 震荡 / 禁止交易`。
2. **位置**：多周期强结构 **区间**（含中心与半宽），补充过去 N 根高低点、前一日高低点和可见等高等低。输出观察区域与失效边界。
3. **动能阶段**：Eric 4H作为阶段背景，1H/30m作短线提示；以普通超买超卖、反转、已确认严格背离、EMA+ADX风险状态区分“扩张”和“衰竭”。输出 `顺势回调 / 潜在反转 / 不明确`。
4. **价格触发**：等待实际扫过区间边缘或过去高低点并收回（SH），随后真实向对应方向突破扫盘前的微结构（BMS代理），可选择回踩确认（RTO代理）。输出有效交易候选与具体失效价。
5. **订单流**：成交量与估算 Delta/CVD 检查主动成交是否推动价格；OI、资金费率在有真实有效数据源时用于背景判断。只有**价格结构失效**、重大数据缺失或执行风险超限才设硬否决；OI/费率不强制同向。
6. **执行与复盘**：按预定风险预算倒推仓位；止损位不可因亏损后扩大；设止盈/时间退出、手续费滑点预算与交易后冷却；记录信号、过滤原因和净收益。

## 3. 建议的交易周期

- **1D**：趋势背景与关键大区域；使用已收盘日K。
- **4H**：中期结构、强区间与 Eric 主波段阶段；仅使用已收盘4H信号。
- **1H**：默认决策/执行周期：扫盘、微结构确认、回踩、止损；最先验证此周期。
- **30m**：辅助观察更细的触发；第一阶段不要与1H混为同一个回测样本或自动补进场。
- **1W**：大背景/远端结构参考，不能强行否决全部短线交易。

周期数越多不意味着质量越高，信号存在滞后且不同周期可能矛盾。强支撑压力脚本会经历Pivot右侧确认、反应窗口、至少两次有效独立测试，**强区间在事后才被认定为强**；回测只能使用当时已确认/当时可见的区域，不能将后来确认的价格区间倒填到过去信号。

## 4. 两个彼此分离的策略模型

### A. 顺势回调扫盘模型（首要研究）

**做多：**

1. 日线/4H结构偏多（预先定义，如高周期收盘价在 EMA200 上方，或已完成的HH/HL）；禁止强趋势反向硬做。
2. 价格回调至已有的强支撑区间或经过预先定义的明显前低，附近还有足够的潜在上涨空间；支持区间优先，不要求中心价恰好被触及。
3. 1H跌破区间下缘/前低一定幅度，又在已收盘K线内收回；排除单纯持续下跌。
4. 在限定K线数内，收盘突破扫盘前微结构高点且K线实体达到预设门槛；随后按策略模式等待BMS价位的回踩并收回。
5. Eric 1H的超卖区回升或**最终确认的**底背离属于加分背景；普通超卖本身不可买入。4H强下跌趋势或强区间失效需谨慎。
6. Delta/CVD可以提示主动卖压受限或转强；OI和费率只能解释仓位环境，不强制同向；若可用数据缺失，按独立的“无订单流”基准策略记录。
7. 止损位放在扫盘低点外、加合理ATR缓冲；止盈至少先定义到最近强压力/不利区间之前（或用固定 R 对照）；空间不足则不做。

**做空对称：** 高周期偏空→回抽强压力/前高→上扫收回→向下微结构突破→回踩失败→风险合格后执行。

### B. 区间边缘反转模型（第二阶段验证）

- 仅在**有明确边界的震荡区间**，或更大周期强支撑/强压力附近研究。不是在单边下跌中看到超卖就抄底。
- 需有位置证据（强区间）、反转证据（1H扫盘收回 + BMS + 可选回踩）、波段证据（Eric反转状态/严格背离）中的至少前两项；Eric仅作分层统计，不作为未经检验的必选门槛。
- 逆势或区间反转用**独立更低风险上限**研究，建议演示/模拟仓位风险预算不高于0.25%权益；此为审慎研究默认值，不是已验证最优参数。
- 出现反方向已确认突破、强区间连续收盘失效、可得收益空间不足时放弃。

### C. 真突破趋势延续模型（暂不自动交易）

在强区域附近，有时不会出现假突破收回，而会出现放量突破并回抽成功。V1.1只模拟扫盘→BMS→回踩，**不覆盖这一独立的趋势突破模型**。必须等单独编写、回测和验证后才作为第三种交易类型纳入策略；不要把没有扫盘的走势硬套成 SH。

## 5. Eric波段信号的正确解释

| Eric标签/状态 | 更稳妥的含义 | 处理方式 |
|---|---|---|
| 普通超买 +40 | 动能扩张至极端，趋势也可能继续 | 进入观察状态，不直接做空 |
| 普通超卖 -40 | 卖方动能扩张至极端，可能继续下跌 | 进入观察状态，不直接做多 |
| 反转超买 | 极端区内的D3开始向内回退，带连续IN/极值退幅过滤 | 支持做空候选，需要位置和价格确认 |
| 反转超卖 | 极端区内的D3开始向内回升 | 支持做多候选，需要位置和价格确认 |
| 最终确认底/顶背离 | 价格与D3在不同极端周期形成的背离，并满足离开极端与可选价格恢复确认 | 反转候选加分，不能直接取代BMS |
| MTF同向共振 | 各来源已收盘快照处于同向状态 | 反映状态关联，不代表同一时刻产生多笔独立信号 |
| EMA+ADX强趋势风险提示 | 用趋势方向和强度标记逆势风险 | 逆势过滤的重要辅助，但不是新的进场信号 |

**注意**：Eric v1.9.10源码已明确写明“未在TradingView编译与逐根回放验证”，其独立Pivot背离、Failure Swing、分位数、EMA+ADX属于实验/旁路。建议把核心波段状态与严格背离分离测试，不一次性启用所有增强门槛。

## 6. 冲突与否决规则（建议先人工执行）

**硬性不交易：**

- 所需时间周期数据未收盘、未准备好，或数据源/合约代码无效。
- 观察区域尚未在该时点完成确认；失效边界已被价格确认打破。
- 尚未达到 SH→BMS 所需时间顺序，或者候选超时、扫盘极值被再次打穿。
- 止损价不在合理方向、止损过近/过远、净收益风险比不足、超出风险/敞口上限。
- 市场条件或图表设置与被研究策略的假设不一致（如合成K线、现货信号直接当合约成交价）。

**软性减分、观察，不必直接否决：**

- 1H出现扫盘但Eric 4H尚在反向波段扩张。
- Delta/CVD、OI、Funding彼此不一致；需解释它们是成交、未平仓还是持仓成本，不能投票。
- 4H与1H阶段不同步；可能是大周期内的局部调整。
- 强区域太宽、离现价太远，或区间重叠但并非同一有效结构。

## 7. 从策略变成可检验规则：第一版默认参数（仅研究起点）

| 组件 | 初始候选值 | 说明 |
|---|---|---|
| 主图/宏观 | 1H / 1D，4H辅助 | 只用已完成K线 |
| 强区域 | v3.3原默认 | 至少2次独立测试、ATR反应、区间半宽与失效设置均保持来源原样；不“历史补画” |
| 波段 | Eric原 LC2→RSI20→Stoch26→K4→D3，±25/±40 | 原始定义不改动；先记录标签，不硬过滤 |
| 价格触发 | V1.1原默认 N=20、micro=3、扫盘后最多5根、回踩最多5根 | 先不要为盈利而扫参数 |
| Delta | 初期关闭，之后A/B测试 | TradingView低周期估算并非逐笔主动成交 |
| OI / Funding | 信息观察，默认不参加自动准入 | 必须知道交易所品种、时间粒度、数据完整性 |
| 风险预算 | 演示：顺势0.5%，逆势0.25% | 上限而非目标，每次名义敞口和实际成交会影响风险 |
| 止损 | 扫盘极值外+ATR缓冲 | 必须在交易前固定；止损可能滑点成交 |
| 止盈 | 固定2R与下一强区域前退出各做一组研究 | 以保守执行价计入手续费、滑点、资金费用 |
| 冷却 | V1.1原默认8根1H | 避免同区间频繁交易 |

以损定量（对价格以USD计、合约单位已正确换算后）：

`数量 = (账户权益 × 风险比例) / (每单位止损价差 × 合约乘数)`

名义敞口上限仍需检查；净风险要包含手续费、滑点、跳空/强平风险。真实永续合约还存在资金费用与标记价格/触发规则的差异。

**示例，仅演示逻辑：** 如果某历史K线发生在已确认支撑区域，下扫后快速收回，但Eric只是“普通超卖”、OI下降，不应立即买入；只有随后出现合格的微结构上破和可选回踩收回，且止损/目标空间合格，才成为允许试算的做多机会。反过来，连续收盘跌破支撑区间，则停止把旧支撑当作有效买入理由。

## 8. 三阶段验证，不提前宣称盈利

**Phase 1 — 基准**：仅用V1.1的价格模式，分开跑“突破确认”“回踩收回”，关闭Delta/Eric强制过滤；统一品种、1H、手续费、滑点、时间区间，记录样本量、PF、期望值、最大回撤。

**Phase 2 — 加入位置**：在过去时点已经确认的v3.3区域附近才接受SH信号；和不加区域的基准对照。注意SR将真实区域延后确认，特别容易发生前视偏差。

**Phase 3 — 增量过滤**：分别加入Eric普通/反转/背离、再加入估算Delta/CVD，逐一做消融研究。OI与Funding只有在可取得历史、正确对齐时再单独测试。不使用多指标“全部同向”的硬性逻辑。

样本外：预先冻结规则，对独立时间段/不同市场阶段（单边牛、单边熊、横盘）验证，注意此前已看过2026年部分数据，不能假称全新样本外。必要时用交易级bootstrap估计收益稳定性。

**历史回测基准（来自用户截图）**：V1.0 的4H净利润-3.21%/6笔/0%胜率；1H -4.06%/53笔/PF0.796；30m -9.80%/82笔/PF0.681。4H与1H/30m的回测起始日期不同，不做严格横向排名。V1.1没有来自用户的新回测验证，这份体系尚不能说明具备正收益期望。

## 10. 推荐的最终整合工程结构

1. **保留两份原始指标**，先不改算法，分开独立显示与报警。
2. **复制V1.1策略形成Research V2.0独立文件**，先仅接入强结构区间的“当时已确认”数据（从指标核心逻辑内部移植，不能跨脚本直接读隐藏变量），输出是否在区域内。
3. 独立评估位置过滤之后，再移植Eric主线的有限状态（普通、反转、最终背离）作**可开关**过滤；实验旁路单独留档。
4. 最后再做数据一致性测试、警报与回测对齐、成本/滑点与样本外验证。
5. 只有策略回测持续合格，才考虑模拟盘；不把课程观察事件直接联动真实下单。

**最终原则：环境→位置→波段阶段→价格确认→订单流反证→风险执行。一个交易信号只能在当时已知的数据基础上成立。**
